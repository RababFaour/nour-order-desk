# API

Base path: `/api/orders`. All bodies are JSON.
Order fields: `id`, `customerName`, `phone`, `productName`, `quantity`,
`unitPrice`, `total`, `status`.
(Check these names against your code and fix any that differ.)

## Endpoints

### GET /api/orders
Returns `200` and an array of orders.

### GET /api/orders/:id
Returns `200` and the matching order, or `404` if the ID does not exist.

### POST /api/orders
Request:
```json
{
  "customerName": "[name]",
  "phone": "[phone]",
  "productName": "Vanilla Candle",
  "quantity": 3,
  "unitPrice": 8
}
```
Response `201`:
```json
{
  "id": "[server-generated id]",
  "customerName": "[name]",
  "phone": "[phone]",
  "productName": "Vanilla Candle",
  "quantity": 3,
  "unitPrice": 8,
  "total": 24,
  "status": "Pending"
}
```
Any `total` or `status` sent by the client is ignored.

### PATCH /api/orders/:id
Send only the fields to change, for example:
```json
{ "quantity": 4 }
```
Response `200` with the updated order (`total` recalculated to 32,
other fields unchanged). The `id` cannot be changed.

### DELETE /api/orders/:id
Returns `204` with no body. Fetching the same ID afterwards returns `404`.

## Validation rules
- `customerName` and `phone`: required, not blank
- `quantity`: positive whole number
- `unitPrice`: number, not negative
- `status`: only `Pending`, `Preparing` or `Delivered`
- `total`: always calculated by the server; the client value is ignored
- `id`: generated by the server; cannot be changed
- PATCH body must be a JSON object with at least one valid field
- Malformed JSON returns `400`, not `500`

## Status codes
| Code | Meaning |
|---|---|
| 200 | OK (list, read, update) |
| 201 | Order created |
| 204 | Order deleted, no body |
| 400 | Invalid input or malformed JSON |
| 404 | Order ID not found |
| 500 | Unexpected server error |
